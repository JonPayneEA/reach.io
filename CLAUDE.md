# reach.io — Claude Code Guide

## Project Overview

**reach.io** is an R package providing hydrometric data pipeline tools for the
[Environment Agency Hydrology API](https://environment.data.gov.uk/hydrology/doc/reference).
It covers the full journey from raw API and WISKI .all sources through to Bronze-tier
Parquet storage, following the Hydrometric Data Framework v1.3 and R Tool
Governance standards.

Target users: EA Flood Forecast Modelling team.

**Scope: input / output only.** `reach.io` gets data into and out of the store
and returns typed S7 objects. Quality control is being moved to a separate
`reach.validate` package and plotting to `reach.viz`; the existing QC code
(`silver.R`) is annotated as moving and should not be extended here.

## Architecture

### Medallion Storage Tiers

| Tier | Status | Description |
|------|--------|-------------|
| **Bronze** | Implemented | Raw ingested data in partitioned Parquet, one file per gauge per year |
| **Silver** | Skeleton (`silver.R`) — QC is moving to `reach.validate` | QC-flagged, deduplicated, unit-normalised data |
| **Gold** | Planned | Derived/aggregated outputs, CAMELS-style attributes |

Bronze paths follow: `bronze/<CATEGORY>/<SUPPLIER>/<DATA_TYPE>/<YYYY>/<dataset_id>.parquet`

- `<YYYY>` is the **observation** year: every writer goes through
  `.write_bronze_by_year()` (`schema.R`), which splits by calendar year.
- Bronze is **append-only**. The `dataset_id` ends in the received date
  (`EA_39001_Q_20260115`), so re-ingesting on a later day adds files.
  `read_bronze()` resolves overlap by keeping the most recently received row
  per (series, timestamp). A second write of the same series and year on the
  SAME day lands on the same path and is **merged** into it (new rows win on
  duplicate timestamps), never replaced - an incremental run after a same-day
  backfill must not lose rows.
- Silver is filed by observation year too (`silver_path(..., year = )`);
  `promote_to_silver()` writes one file per `dataset_id` and year.
- WISKI stations can hold several series of one type; the trace code is part of
  the `dataset_id` (`WISKI_3401TH_H_sg_ds_20260115`) and selected with
  `read_bronze(trace = )`. `download_hydrology(output = "disk")` adds a
  period + value-type trace (e.g. `15min_instantaneous`) only when a station
  has several selected measures of one data type.
- Every file written gets a provenance record in
  `<root>/register/hydrometric_data_register.csv`.

### Source Systems

Data is routed from three source systems:
- **HDE** — EA Hydrology API (primary)
- **WISKI** — KiWIS REST API (draft — not yet operational)
- **WISKI_ALL** — WISKI .all export files (default bulk import method)

The `router.R` functions (`route_gauge()`, `fetch_from_hde()`, etc.) dispatch
to the correct source.

### S7 Classes

All returned data objects are typed S7 classes defined in `classes.R`.
Classes encode parameter (Rainfall, Flow, Level), period (Daily, 15min, Hourly),
and supply metadata slots. Downstream code should work with S7 objects
regardless of which store tier data comes from.

## Key Functions

### Setup
- `setup_hydro_store(path)` — Create directory structure for all tiers

### Discovery
- `find_stations(...)` — Query EA API by WISKI ID, RLOIid, notation, name, or proximity
- `get_measures(station_id)` — List available measures for a station

### Download
- `download_hydrology(parameters, from_date, to_date, method, output, out_dir, ...)` —
  sync or batch API download. `output = "memory"` returns S7 objects;
  `output = "disk"` writes year-partitioned Bronze Parquet + provenance (both
  methods). `to_date` is **exclusive**.
- `run_sync()` / `run_batch()` are internal per-measure workers.

### Read
- `read_bronze(root, gauge_id, data_type, supplier_code, category, start, end, trace)` —
  Bronze → S7 object; `read_bronze_multi()`, `read_bronze_catchment()`
- `read_silver()` / `read_silver_multi()` / `read_silver_catchment()` — Silver → S7 object
- `*_catchment()` readers accept the registry that `build_gauge_registry()` writes
  (`gauge_id` + `catchment`) as well as `site_id` + `catchment_id`, and de-duplicate gauges

### Pipeline
- `build_gauge_registry(csv_path, output_path)` — registry keyed on `gauge_id` + `data_type`
- `route_gauge(gauge_row, start_date, end_date, on_error)` — dispatch to the source system;
  orchestrators use `on_error = "stop"` so failures are logged `FAILED`, not `EMPTY`.
  With `"stop"`, `fetch_from_hde()` / `fetch_from_wiski_all()` also raise for an unknown
  gauge, a missing measure/file, or a failed annual chunk (never a silent partial series).
- `run_backfill(registry_path, output_dir, start_date, end_date, ...)` — batched, checkpointed
  backfill; `failed_only = TRUE` re-runs failures and merges into the log
- `run_incremental(registry_path, output_dir, ...)` — fetch from each gauge's high watermark
  (`get_high_watermark()`); skips `live = FALSE` registry rows
- `ingest_all_file(path, output_dir, tz = "UTC", ...)` — WISKI `.all` export → Bronze

### Catalogue
- `list_available_gauges()` — List all gauges in Bronze store
- `summarise_coverage()` — Date ranges and completeness per gauge
- `check_gaps()` — Identify missing timesteps

### Rating Curves
- Defined in `rating.R` and `rating_store.R`
- S7 class-based lifecycle; see `vignettes/rating-curve-lifecycle.Rmd`

### Silver (QC moving to `reach.validate`)
- `promote_to_silver(data, ...)` — QC-flag and promote Bronze data to Silver tier
- QC flags: 1=Good, 2=Estimated, 3=Suspect, 4=Rejected
- `snap_offgrid_timestamps()` — standalone 15-min grid resolution (15-min data only)

## Development Conventions

### Language & Dependencies
- **R** package; uses `S7` for OOP, `data.table` for tabular data, `arrow` for Parquet I/O
- `future` / `future.apply` for parallelism
- `httr` for API calls. `ggplot2` is *suggested* only (optional plots); dates use base R
  and data.table (`lubridate` is confined to reach.utils)

### Testing
Run tests with:
```r
devtools::test()
# or for a specific file:
testthat::test_file("tests/testthat/test-silver.R")
```

Tests use `testthat` edition 3. All test files live in `tests/testthat/`.

### Documentation
```r
devtools::document()   # regenerates NAMESPACE and man/ from roxygen2
devtools::build_vignettes()
```

### Code Style
- Follow existing S7 class patterns in `classes.R` when adding new data types
- New data types require entries in `DATA_TYPE_CODES` (schema.R) and
  `setup_hydro_store()` (setup.R) before ingestion tools can be written
- Bronze schema columns: `timestamp`, `value`, `supplier_flag`, `dataset_id`,
  `site_id`, `data_type`
- Provenance records written to Hydrometric Data Register on each ingest
- Code that takes a function argument named like a table column (`site_id`,
  `data_type`, `category`, `tier`, ...) must not use it inside `dt[...]`: the
  column wins. Use `.filter_rows(dt, "col", value)` or compute `which(...)` first.
- Build `POSIXct` for Parquet as doubles — `seq(<POSIXct>, by = ...)` can be
  integer-backed and arrow mis-writes it (the writers normalise, but fixtures
  that call `arrow::write_parquet()` directly must too).
- Tests: `expect_message(x <- f(), "...")` (edition 3 returns the condition, not the value).
- Tests never sleep: the EA fair-use pause goes through `.pace()` (mocked in `setup-pace.R`).
  Every bug fix gets a regression test that was checked to fail on the old code.
- `diff()` of POSIXct is a difftime with auto-chosen units: use
  `as.numeric(diff(x), units = "secs")` before dividing.
